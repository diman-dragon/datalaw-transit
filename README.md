# DataLaw Transit

Офлайн-приложение с расписанием общественного транспорта Белграда (Capacitor 8, Android).
Данные — открытый GTFS с data.gov.rs. **Приложение само никуда не ходит**: расписание скачивается
только по кнопке «Скачать / обновить данные» в настройках (или берётся из zip-файла на телефоне).

## Что умеет

- Поиск линий и остановок (кириллица и латиница работают одинаково, поиск по коду остановки).
- Остановка: ближайшие отправления и полное расписание по линиям, выбор дня (в т.ч. праздничные исключения, рейсы за полночь).
- Линия: описание маршрута (список остановок по направлениям, варианты), расписание на любой остановке.
- Карта линии: ломаная по остановкам (вкладка «Карта» на странице линии), подложка OpenStreetMap по желанию.
- «Из А в Б»: линии без пересадок между двумя остановками (по названию), время в пути, ближайшие отправления и участок на карте.
- Направление везде подписано как «Начальная → Конечная» (например, «Мириево 4 → Дорчол»).
- Избранные остановки (с ближайшими отправлениями) и линии.
- Настройки: тема «Тёмная AMOLED» / «Светлая, светло-коричневая», данные, версия приложения.
- В планах (заготовки в `src/planned/`): построение маршрутов A→B и время прибытия в реальном времени.

## Сборка APK без Android Studio (только GitHub)

1. Создайте **приватный** репозиторий на GitHub и загрузите туда содержимое папки
   (в репозитории лежит ключ подписи `keystore/` — поэтому приватный).
2. Вкладка **Actions → Android APK**: сборка стартует после push, либо «Run workflow».
3. По окончании скачайте артефакт `DataLaw-Transit-apk`, распакуйте, установите APK на телефон.
4. Ключ подписи постоянный (`keystore/datalaw-release.jks`), а `versionCode` всегда растёт, поэтому новая сборка
   ставится **поверх** установленной, без удаления (данные и избранное сохраняются).
   Отпечаток ключа (SHA-256) виден в итогах каждого запуска Actions — он должен совпадать от сборки к сборке.
   Не удаляйте и не пересоздавайте keystore: с другим ключом Android потребует сначала удалить приложение.

Первая сборка создаёт папку `android/` командой `npx cap add android`. Если хотите, закоммитьте её потом.
Версия приложения берётся из `package.json` (`version`) — поднимайте её перед сборкой.

## Первый запуск на телефоне

Настройки → **Скачать / обновить данные**. Скачиваются два фида (городской и пригородный, ~7 МБ каждый максимум),
обработка занимает до минуты. Если портал не отдаёт файл, откройте «Ссылка и загрузка из файла» у нужного источника
и выберите zip, скачанный вручную.

## Разработка в VS Code

```
npm install
npm test          # тесты импорта GTFS, расписания и поиска
npm run dev       # веб-версия в браузере (скачивание с data.gov.rs может блокироваться CORS — используйте «из файла»)
npm run typecheck
```

## Иконка

Сгенерирована из `resources/logo-source.png`. Сейчас: тёмно-синий фон `#0D2038`, светлый логотип D и янтарный значок автобуса (`TRANSPORT_BADGE` в скрипте).
Другие варианты (`cream`, `white`, `black`, `brown`) — `python3 scripts/make_icons.py --variant cream`
(нужны Pillow и numpy), затем закоммитьте `resources/` и `public/`. Лист сравнения — `resources/icon-variants.png`.

## Структура

- `src/gtfs/` — разбор GTFS (CSV, сборка линий/вариантов/рейсов), работает в Web Worker.
- `src/db.ts`, `src/store.ts` — IndexedDB и данные в памяти. `src/schedule.ts`, `src/search.ts` — логика расписания и поиска.
- `src/ui/` — экраны. `src/planned/` — точки расширения под маршруты и реальное время.
- `scripts/prepare-android.mjs` — иконки и версия в Android-проекте. `.github/workflows/android.yml` — сборка.
