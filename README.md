# DataLaw Transit

Офлайн-приложение с расписанием общественного транспорта Белграда (Capacitor 8, Android).
Данные — открытый GTFS с data.gov.rs. **Приложение само никуда не ходит**: расписание скачивается
только по кнопке в настройках (или берётся из zip-файла на телефоне).

Внимание: официальный GTFS обновляется нерегулярно и может отставать от реальных изменений на линиях.
Срок действия данных всегда виден в приложении.

## Что умеет (версия 1.1.0)

Три раздела: **Поиск**, **Избранное**, **Настройки**. Карты, пересадок и маршрутов «из А в Б» в приложении нет.

- Поиск линий и остановок (кириллица и латиница работают одинаково, поиск по коду остановки).
- Линия: расписание **только от конечной остановки** по направлениям: «Будни / Суббота / Воскресенье».
  Сегодняшний тип дня выбран сразу и помечен точкой «сегодня» (праздник, идущий по-воскресному, распознаётся).
  Над сеткой указано, с какой даты и по какую действует расписание (зимнее и летнее — разные периоды).
  Вкладка «Остановки» — полный список остановок направления, без времён.
- Остановка: какие линии здесь проходят; если остановка начальная — отправления отсюда.
- Избранное: остановки и линии (для линий — ближайшее отправление от конечной сегодня).
- Настройки: тема «Тёмная AMOLED» / «Светлая, светло-коричневая», данные, версия приложения.
- Направление везде подписано как «Начальная → Конечная» (например, «Мириево 4 → Дорчол»).
- Полностью офлайн. Интернет нужен только для кнопки скачивания данных.

## Данные: скачать, сравнить, применить

Настройки → **Скачать / обновить все источники**. Приложение скачивает GTFS (городской и пригородный фиды),
собирает данные и **ничего не заменяет сразу**: сначала показывает сравнение с текущими данными:

- срок действия: «сейчас действует … → новое расписание …» (предупреждение, если новый файл старше текущего);
- новые линии, убранные линии, изменённые линии (рейсы +/−, первый и последний рейс, смена конечных);
- сравнение идёт по типичным дням (будни, суббота, воскресенье), даты показаны в отчёте.

Кнопки **Применить** / **Отмена**. Отчёт о последнем обновлении остаётся в настройках.

Вручную: у каждого GTFS-источника — «Скачать этот источник» (только он) и «Выбрать zip вручную…»
(скачанный в браузере файл GTFS). Ручной файл проходит то же сравнение. «Пересобрать из сохранённых файлов» —
собрать данные заново из zip, уже лежащих в памяти приложения, без интернета.

## Свой файл расписания (gsp.rs)

Официальный GTFS обновляется редко, поэтому есть третий источник — **свой файл `datalaw-schedule.json`**,
который собирает скрипт `tools/collect_gsp.py` с сайта gsp.rs (PDF расписаний от конечных + списки остановок).

```
pip install -r tools/requirements.txt
python tools/collect_gsp.py                 # скачает всё в cache/ и создаст datalaw-schedule.json
python tools/collect_gsp.py --only 26,72    # только выбранные линии (для проверки; id как в linija.aspx?id=…)
python tools/collect_gsp.py --debug-pdf cache/pdf/26.pdf   # показать, как разобран один PDF
python tools/test_collect_gsp.py            # тесты разбора
```

В конце скрипт печатает «Замечания»: линии без PDF, без направлений, с нераспознанной таблицей.
Файл перенесите на телефон и выберите: Настройки → Источники → «Свой файл расписания» → «Выбрать файл расписания…».
Он проходит то же сравнение со старыми данными. После загрузки приложение предложит отключить GTFS, чтобы линии не дублировались.

**Важно:** скрипт написан по описанию страниц gsp.rs и проверен только на синтетических PDF и HTML. Если на настоящем сайте
таблица разберётся неверно, запустите `--debug-pdf` на PDF одной линии и пришлите вывод — парсер подправим.
Идентификаторы остановок в таком файле — их названия, поэтому остановки с одинаковым названием в разных направлениях
считаются одной остановкой (координат у gsp.rs нет).

Формат файла описан в начале `src/custom.ts`: линии → направления → остановки, «Важи од» (`validFrom`) и времена
`weekday` / `sat` / `sun` в виде «ЧЧ:ММ» (после полуночи — 24:15, 25:05…). Файл можно составить и вручную.

## Напоминания

Настройки → Напоминания. Приложение ничего не скачивает само, но при открытии показывает баннер сверху:
за 7 дней до смены расписания (даты по умолчанию 15.06 и 01.09 — поменяйте под себя), после смены, пока данные не обновлены,
за 14 дней до конца срока и когда данные старше 60 дней. Кнопки: «Скачать новое» (в настройки) и «Напомнить завтра».
Напоминание видно только при открытии приложения (уведомлений на экран телефона нет).

Если в приложении уже были данные от версии 0.x, откройте Настройки и нажмите «Пересобрать из сохранённых файлов»
(формат данных изменился: убраны карта и координаты).

## Сборка APK без Android Studio (только GitHub)

1. Создайте **приватный** репозиторий на GitHub и загрузите туда содержимое папки
   (в репозитории лежит ключ подписи `keystore/` — поэтому приватный).
2. Вкладка **Actions → Android APK**: сборка стартует после push, либо «Run workflow».
3. По окончании скачайте артефакт `DataLaw-Transit-apk`, распакуйте, установите APK на телефон.
4. Ключ подписи постоянный (`keystore/datalaw-release.jks`), а `versionCode` всегда растёт, поэтому новая сборка
   ставится **поверх** установленной, без удаления (данные и избранное сохраняются).
   Отпечаток ключа (SHA-256) виден в итогах каждого запуска Actions — он должен совпадать от сборки к сборке.
   Не удаляйте и не пересоздавайте keystore: с другим ключом Android потребует сначала удалить приложение.

Первая сборка создаёт папку `android/` командой `npx cap add android`. Если хотите, закоммитьте её потом.
Версия приложения берётся из `package.json` (`version`) — поднимайте её перед сборкой.

## Первый запуск на телефоне

Настройки → **Скачать / обновить все источники** → проверьте сравнение → **Применить**.
Обработка занимает до минуты. Если портал не отдаёт файл, откройте «Ссылка и ручная загрузка» у нужного источника
и выберите zip, скачанный вручную.

## Разработка в VS Code

```
npm install
npm test          # тесты импорта GTFS, расписания, сравнения и поиска
npm run dev       # веб-версия в браузере (скачивание с data.gov.rs может блокироваться CORS — используйте «из файла»)
npm run typecheck
```

## Иконка

Сгенерирована из `resources/logo-source.png`. Сейчас: тёмно-синий фон `#0D2038`, светлый логотип D и янтарный значок автобуса (`TRANSPORT_BADGE` в скрипте).
Другие варианты (`cream`, `white`, `black`, `brown`) — `python3 scripts/make_icons.py --variant cream`
(нужны Pillow и numpy), затем закоммитьте `resources/` и `public/`. Лист сравнения — `resources/icon-variants.png`.

## Структура

- `src/gtfs/` — разбор GTFS (CSV, сборка линий/вариантов/рейсов), работает в Web Worker.
- `src/db.ts`, `src/store.ts` — IndexedDB и данные в памяти. `src/schedule.ts`, `src/search.ts` — логика расписания и поиска.
- `src/custom.ts` — формат своего файла расписания. `src/remind.ts` — напоминания. `tools/collect_gsp.py` — сборщик.
- `src/compare.ts` — слепок расписания и сравнение старых данных с новыми. `src/importer.ts` — загрузка, подготовка и применение обновления.
- `src/ui/` — экраны.
- `scripts/prepare-android.mjs` — иконки и версия в Android-проекте. `.github/workflows/android.yml` — сборка.
