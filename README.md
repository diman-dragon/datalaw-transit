# DataLaw Transit 2.0.0

Офлайн-приложение с расписанием общественного транспорта Белграда (Capacitor 8, Android).
Приложение **ничего не скачивает само**: расписание загружается из JSON-файла в настройках.

## Что в приложении

Три вкладки внизу: **Избранное** (слева, открывается первой), **Линии** (в центре), **Настройки** (справа).

- **Избранное.** Карточка линии: номер слева, справа две строки в рамках — обе конечные, между ними стрелки ⇅.
  Под названием каждой конечной — ближайшее отправление от неё («14:25 · через 12 мин», после последнего рейса — «завтра 04:10»).
  Названия всегда в одну строку (без переносов). Нажатие на строку открывает линию в этом направлении.
- **Линии.** Поиск (по номеру и по конечным), фильтр-сетка: Все / Трамваи / Тролл. / Дневные / Ночные / Экспресс / Пригор. / Сербиявоз
  (показываются только категории, которые есть в файле), выровненная сетка номеров. Прокручивается только список.
- **Линия.** Закреплённый блок: номер (и ★) → карточка направления (нажатие меняет направление) → Будни / Суббота / Воскресенье
  (сегодняшний день выбран и помечен) → «Расписание» (мелко — срок действия) и «Остановки» (пока неактивно).
  Ниже прокручивается только расписание «час — минуты»; для сегодняшнего дня оно сразу прокручено к текущему часу, ближайший рейс выделен.
- **Настройки.** «Загрузить расписание» (с проверкой файла и уведомлениями), формат файла, тема, версия.
- **Системная «назад»**: закрывает окно → на шаг назад → с «Линий»/«Настроек» в «Избранное». В «Избранном» ничего не происходит.
- **Напоминание**: раз в месяц, при первом открытии, окно «Проверьте расписание».

## Формат файла расписания

JSON (`.json`, UTF-8, до 25 МБ), метка `"format": "datalaw-schedule/1"`. Структура описана в начале `src/validate.ts`:

```json
{
  "format": "datalaw-schedule/1",
  "validTo": "2026-12-31",
  "lines": [{
    "id": "26", "short": "26", "long": "Дорћол - Браће Јерковић",
    "kind": "bus", "category": "day",
    "dirs": [{
      "from": "ДОРЋОЛ", "to": "БРАЋЕ ЈЕРКОВИЋ", "validFrom": "2025-03-17",
      "times": { "weekday": ["04:10", "24:15"], "sat": ["05:00"], "sun": ["06:00"] }
    }]
  }]
}
```

- `kind`: `bus` | `tram` | `trolley` | `rail` | `other` (по умолчанию `bus`).
- `category` (необязательно): `day`, `night`, `express`, `suburban`, `rail`, `tram`, `trolley`; либо `"night": true`.
  Если не указано, определяется само: трамвай/троллейбус/электричка — по `kind`, `N1`/`15N` — ночные, `E…`/`A…` — экспресс, номера от 300 — пригородные, остальное — дневные.
- Время после полуночи пишется как 24:15, 25:05 … (до 47:59).
- Первое направление — «туда», второе — «обратно»; больше двух не используется.

**Проверка при загрузке.** Файл отклоняется (с понятным сообщением), если он пуст, больше 25 МБ, это ZIP/PDF, не UTF-8, не JSON,
нет метки формата или версия не та, нет ни одной линии с отправлениями. Мелкие проблемы (некорректное время, неверная дата, повтор id,
линия без направлений, истёкший срок, файл старее загруженного, пропавшие линии из избранного) — это «замечания»:
они показываются в окне подтверждения, а файл всё равно можно загрузить (проблемные данные пропускаются).

Файл делает `tools/collect_gsp.py` (ночные линии помечаются `"category": "night"`):

```
pip install -r tools/requirements.txt
python tools/collect_gsp.py
```

## Что убрано относительно 1.x

Скачивание из сети (data.gov.rs), GTFS-архивы, сравнение версий, поиск и экран остановок, настройка дат смены, недавние запросы,
остановки в избранном. Старые данные 1.x не читаются — после обновления загрузите файл расписания; избранное линий `g:…` сохранится.

## Разработка

```
npm install
npm test          # проверка файла, расписание, поиск, напоминание
npm run typecheck
npm run dev
```

## Сборка APK (GitHub Actions)

Как раньше: приватный репозиторий → Actions → «Android APK». Ключ подписи `keystore/` постоянный, `versionCode` растёт,
APK ставится поверх. Версия берётся из `package.json` (сейчас **2.0.0**).

## Структура

- `src/validate.ts` — формат и проверка файла. `src/dataset.ts`, `src/db.ts`, `src/store.ts` — набор данных, IndexedDB, память.
- `src/schedule.ts` — тип дня, ближайшее отправление, сортировка. `src/search.ts`, `src/format.ts`, `src/remind.ts`, `src/prefs.ts`.
- `src/ui/` — экраны (`fav-view`, `lines-view`, `route-view`, `settings-view`), навигация и «назад» (`nav.ts`), уведомления и окна (`overlay.ts`).
